# WhereverCode V5 双端 UI 适配组装任务书

日期：2026-11-15
目标仓库：huaerdaidai-gif/wherevercode-agent（不得改旧仓库 wherevercode）
交付基线：WhereverCode_V5_双端UI组装基线_v2.zip

## 不可变更的产品约束
1. 首页严格以用户指定的 Claude 风格截图为视觉基线：顶部两个按钮、中部星芒与问候、底部输入框；不加底部导航、快捷卡片、统计卡片。
2. 一级抽屉仅四项：对话、工作台、控制台、设置；全局控制台与其他菜单视觉同级；二三级逐层收纳。
3. 70 路由是最低功能覆盖要求，不得因菜单收纳而删除功能。Android Jetpack Compose 与 iOS SwiftUI 保持相同路由、术语、状态、操作和设计规范。
4. 不得把原型/占位说成真实可用。保留现有 App、鉴权、数据迁移、任务状态机和业务逻辑，不整体替换 MainActivity 或 SwiftUI 入口。

## 工作分解（可并行派给不同 Agent，角色不固定）
A. 基线与差距审计：检查仓库当前主线和交付 ZIP，生成 route_id→现有文件/函数/API/权限/状态/测试 的完整映射；比对仓库 docs/p0/screens-18.csv、ui-backend-70.csv（若存在）及原包验收表；不得猜测端点。
B. Android UI：将 70 路由纳入现有 Compose 导航与页面体系，首页像素级遵循参考图，四父级抽屉；接入真实能力适配器。保留旧逻辑和兼容性；编译及回归。
C. iOS UI：同路由、同视觉和行为实现 SwiftUI；平台差异仅限系统权限、文件选择、通知、后台运行等；提供可复现构建和真机/模拟器证据。
D. 后端接线：逐项核实真实 API、SSE/WebSocket/MCP、鉴权/权限、幂等、超时、错误码、重连与离线；没有接口的写缺口单，不造假接口。特别覆盖任务、派单、审批返工、设备/Agent、事件、自动化与控制台。
E. 集成与验收：合并前审查，端到端验证 70/70 route_id 可达；逐项区分“已接通/仅展示/待开发/不可用”；覆盖权限拒绝、断线、暂停/停止确认、重复操作、失败回滚、旧数据迁移。

## 交付格式
每个 Agent 交付：分支、commit、改动文件清单、路由覆盖表、真实接口证据、测试命令与结果、截图/录屏（注明真机或模拟器）、未完成事项、风险及回滚方式。
验收门禁：不得以 HTML 可点通代替原生可运行；不得以静态 mock 数据代替真实后端；未经测试不标“完成”。

## 安全和协作
只在 wherevercode-agent 新分支开发；禁止触碰旧仓库 wherevercode；禁止未经批准部署生产或公开仓库；不要上传令牌、私钥、签名证书；对权限敏感操作执行服务端校验；每个阶段先交差距与证据，再提交代码。
