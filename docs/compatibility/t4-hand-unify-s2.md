## 1. 唯一手写源与生成方式

- 唯一手写实现：server/hand_server.py。
- 生成资产：android/app/src/main/assets/install/hand_server.py，提交到 Git。
- 新增 scripts/sync_hand_server.py，只依赖 Python 标准库。
- 默认检查模式（或 --check）：按原始字节比较两处，缺文件或不一致退出非零；输出路径、SHA-256 与修复命令，不修改文件。
- 显式 --write：将主文件字节原样写到资产，使用同目录临时文件和原子替换；从脚本位置解析仓库根目录，不依赖当前工作目录。
- 两份都带相同文件头说明：此路径若位于 assets/install 则为生成物，修改 server/hand_server.py 后运行同步脚本。不要只给资产加额外头部，否则内容版本会不一致。
- UTF-8/LF；检查不做换行或空白归一化，git 属性仅对这两个路径固定 LF。
- 不生成第二套模板、片段库或运行时 shim；目标机仍可拿单文件独立执行，不依赖仓库目录和脚本。

选择显式脚本同步而非构建时悄悄覆盖：Git 审查可看见资产变化；防漂移检查能真实失败；现有 App assets 读取路径不变。内容 SHA-256 前 12 位继续作为安装/更新版本，主文件和资产版本相同。构建验证只检查，不自动修复漂移。

### H05/H07：配置策略必须显式，不按文件路径猜测

A/B 对“同 ID command 谁优先”和“注册目录是否自动授权”的行为互相冲突。用一个配置策略参数保留两种现有入口的行为，策略只决定配置解析和授权来源，不复制执行/控制逻辑：

| 策略 | command 优先级 | 授权目录 | 使用方式 |
|---|---|---|---|
| standalone（默认） | 显式 agents.json.command 优先；无旧 command 时才用注册表 | auth.json（兼容 list/dict.folders）+ 当前客户端 project_grants；发现目录不自动授权 | 现有 A 的无参数启动保持权限边界 |
| bundled | 保留 B：注册表已有 ID 时 registry argv 优先，旧 command 冲突记审计；未知 ID 保留旧 command | 保留 B：显式授权 + 配置/注册目录 + 当前客户端 project_grants | 安装脚本启动参数明确指定 |

具体接口：全局参数 --config-policy=standalone|bundled；HandServer 新增尾部可选参数，旧调用保持兼容。参数随服务启动命令传入，不新增状态数据库，不依赖自动探测迁移。

- shell/PowerShell 安装脚本写入的服务启动命令显式选择 bundled；覆盖所有受支持的服务后端。
- 自更新 apply/rollback 和 watchdog 重启必须保留原启动策略与原参数，不能更新后回到默认而改变权限。
- 旧 B 手工部署升级到统一文件时，文档明确要求显式 bundled；不改写现有 auth.json、agents.json 或密钥。无法核实启动方式的设备不自动升级。
- 两种策略都可用所有新增能力（配对、mDNS、WS、MCP 等）；standalone 中新发现 Agent 的目录须先 grant，不能绕开授权。
- MCP 的授权集合也服从同一策略。project_grants 仍按客户端隔离，不能提升为全局授权。
- 策略值错误直接报错。测试同时覆盖两种策略；不能用跳过 A 测试实现“兼容”。

这是一项需要 Muse 在本 S2 明确复核的冲突取舍；未通过前不实现。若后续实现发现还存在无法由此规则解释的冲突，在该项停下报告。

## 6. S6 设备链路与有界控制

设备/模拟器必须能够访问测试 Hand 和实际 CLI；使用隔离 state-dir、测试目录、测试身份，不动现网密钥/授权。当前尚无设备执行证据，不将 CI 或 socket mock 算真机验收。

链路：mDNS 发现→密封配对→App 创建并派发真实任务→暂停→恢复→停止→结果回读。
- 记录统一源码 SHA/内容版本、App 构建、设备/网络条件、task/attempt、每步时间；日志不含密钥、凭证或配对码。
- 真实任务在测试目录持续产出可观察的进度文件，记录 Agent 进程树/PID；暂停后观察产出停止，恢复后继续，停止后进程树消失且无后续写入。
- 本次验收预设：稳定测试网络下，从控制发出到进程真实生效 pause/resume 各 <= 2 秒、stop <= 5 秒；暂停稳定观察 >= 3 秒，停止后观察 >= 5 秒。报告实测值，超界算失败，不能只凭 UI 状态通过。
- 结果回读验证 task/attempt 对应的真实产物与摘要；若受控停止按既有语义不产生成功 artifact，明确记录停止终态/回读错误，并另用同一链路中的成功执行轮次验证 artifact，不能伪造停止任务的成功结果或改变状态机。
- 逐步留脱敏日志和截图；发现/配对/派单/控制/结果分别映射 S1 ID。设备或执行通道不足时 S6 列未完成，不声称统一完成。
