## プロジェクト概要

WhereverCode Agent は、AI 対話、プロジェクトファイル、タスク実行、複数 Agent の協調、デバイス制御を**シンプルで機能豊富な**モバイルワークスペースに統合することを目指します。Agent の役割やモデルを特定のベンダーに固定せず、タスクに応じて選択し、人が進捗・承認・結果を監督します。

この `wherevercode-agent` は独立したアプリであり、旧 `wherevercode` オーケストレーション基盤とは別のリポジトリです。基本的な単独 Agent 機能は旧基盤やチャンネルへの依存を前提としません。遠隔協調には実際のサービスと権限が必要です。

## 製品体験と Android / iOS の統一

目標は **Claude / Codex のような簡潔さ、ドロワーによる整理、機能を削らない設計**です。両プラットフォームで情報設計、メニュー名、状態、権限の意味をそろえます。

| 領域 | 目指す体験 |
| --- | --- |
| **チャット** | 会話、Agent / モデル選択、タスク開始、実行フィードバック |
| **プロジェクト** | プロジェクトソース、ファイル、コンテキスト、成果物、関連タスク |
| **チャンネル / 協調** | 権限のあるチャンネルでの連絡とタスク追跡。存在しないサーバー API は仮定しない |
| **コントロール** | デバイス、Agent、モデル、接続、実行状態、監査、高度な設定 |

これは**製品目標**であり、現在の `main` で完全に一致したという意味ではありません。2026-11-19 の両端監査ではチャンネル導線やコントロール画面などに差異があり、実際のコードとスクリーンショットでの確認が必要です。

## ビルドとインストール

### Android

[android/README.md](android/README.md) と最新の Gradle 設定を参照してください。開発文書には JDK 17、Gradle 8.2.1、SDK 34、Chaquopy 15.0.1、Python 3.11 が記載されています。互換環境と `JAVA_HOME` / `ANDROID_HOME` を設定後：

```sh
./scripts/build-android-p0.sh
```

完全な Gradle Wrapper がない場合があります。デバッグ署名の APK は正式な更新パッケージではありません。APK のビルド成功は Node ランタイムや Agent CLI の動作証明ではありません。

### iOS

ネイティブ Swift / SwiftUI プロジェクトは [ios/README.md](ios/README.md) を参照してください。ビルドには対応する macOS / Xcode、インストールには署名が必要です。未署名 IPA はそのままインストールできる正式版ではありません。過去のサーバー API 説明は再確認が必要です。

未確認の APK / IPA ダウンロードリンクは掲載しません。

## セルフデプロイ（シングル Agent 版、今すぐ使えます）

サーバーは不要で、誰かのアカウントや許可も必要ありません：

1. **App をインストール**：本リポジトリの Release から署名済み Android パッケージをダウンロードして直接インストールします。iOS は未署名パッケージをダウンロードし、Sideloadly / AltStore で自分の Apple ID を使って自己署名してください。
2. **無料モデルの key を入力**：App の「コントロール → モデル」には無料モデルプロバイダ 6 社のプリセット（Google AI Studio、OpenRouter、Groq、SiliconFlow、智譜 GLM、Cloudflare Workers AI）があります。各社のサイトで登録し、key を App に入力すれば、ゼロコストで対話を始められます。有料モデルは完全に任意で、デフォルトではスマートルーティングに入りません。
3. **デバイスを接続（Hand、1 行コマンド）**：作業を任せたいパソコン／スマホでターミナルを開き、App に表示される Hand コマンド 1 行を貼り付けて Enter を押すだけ——デバイスとその上の Agent が App に検出され、Agent を選んで対話したりタスクを割り当てたりできます。Hand は別途インストールするプログラムではなく、全デバイス共通です。

**マルチ Agent チャンネルについて**：チャンネル協働（複数の Agent が同一チャンネルで作業をリレーする機能）は MCP サーバーコンポーネントに依存しますが、本リリースには実行可能な MCP サーバーはまだ含まれていません。第 1 档／第 2 档／第 3 档として段階的に公開します。デプロイ形態は確定済みです：ローカル（同一デバイス、App に統合、ゼロデプロイ）／LAN／クロスデバイス（公網・メッシュリモート）の 3 トポロジすべてで全機能が利用でき、機能低下はありません。デプロイが必要な場合でも、ターミナルに 1 行貼り付けるだけです。それまでは、本リリースの利用範囲は上記のシングル Agent モードです。

## アーキテクチャ原則

- **モデル・Agent の交換可能性**：推論役と実行役を特定のベンダーに固定しない
- **ローカル優先、遠隔は任意**：遠隔アクセスには明示的な許可が必要
- **人による制御**：一時停止、停止、目標変更、承認、再試行は実際の実行応答に従う
- **追跡可能な実行**：要求、配信、実行中、確認済み、失敗、確認待ちを区別
- **最小権限**：ファイル書き込み、ツール、デバイス、認証情報を保護し、失敗を成功と報告しない
